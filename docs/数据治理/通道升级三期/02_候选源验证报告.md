## 一、逐候选验证结论

### 候选1：P69 美国零售 → 东财/akshare 零售销售（`macro_usa_retail_sales`）——**否决，口径不同**

- akshare/东财的"美国零售销售"只有**月率%**（事件口径，且数据停在 2025-08，滞后一年+）；
- P69 现口径 = **零售和食品服务销售额绝对值（季调，百万美元）**，FRED RSEAS 系列；
- 换成百分比=改口径，触发红线2。**否决**。

### 候选2：P69 → 普查局官方 MRTS API（`api.census.gov`，RSEAS 的一手来源）——**保留为备选，不作主通道**

- 口径完全一致（RSEAS 即 MRTS 44X72 SM 季调的转发），但**本机到普查局的线路与 FRED 同病**（20s 读超时实测）；
- 结论：主通道维持 FRED 直连+Wayback 兜底，MRTS API 登记为文档化备选。

### 候选3（本部分关键发现）：P69 超时的**真正根因不是线路，是系统代理劫持**

- P69 采集器是全项目唯一用**裸 requests**（trust_env=True）的：桌面系统代理拉起时被劫持到不稳线路→超时；
- 其余采集器走 `common.http_get`（显式直连，二期C2加固）从未出现同类问题；
- 实测同一时刻：直连 FRED 1.9s 成功、显式代理 ProxyError——与日志中"P69 单独持续超时"完全吻合；
- **修复：P69 改走 common.http_get（同源同口径零变化）**，见 03 报告。

### 候选4：P4 美债 → akshare `bond_zh_us_rate`（新浪债券）——**登记为备用通道**

- 实测新鲜可用（2026-10-30 = 4.94%，与现值连续），10Y 口径一致；
- 主通道维持美国财政部官网（官方一手），akshare 接口登记入注册表备注作为降级链。

### 候选5：P2 CPI → akshare `macro_usa_cpi_monthly`——**否决**

- 事件口径月率%且滞后（停在 2025-09），四维全面劣于现源 OECD SDMX 官方同比。保留 OECD。

### 候选6：P24/P25 汇率 → akshare `currency_boc_sina`——**否决**

- 连接被远端重置（10054），稳定性劣于现用新浪行情直连。P24/P25 维持现状（二期已定论：东财无直盘）。
