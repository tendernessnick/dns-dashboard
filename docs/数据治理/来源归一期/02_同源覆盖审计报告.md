## F1 关键发现：东财 push2 系"渐进式限流"（实测）

对 `push2.eastmoney.com`（实时快照）与 `push2his.eastmoney.com`（日K历史）的当天全量实测时间线：

| 时间（10-30） | 动作 | 结果 |
| --- | --- | --- |
| 会话初 | 裸测 2 次（实时+日K） | 均 200 正常 |
| 采集器批量复跑 | 5 条 push2his 依赖采集器 | 全部 `RemoteDisconnected`（P23 走 push2 实时正常） |
| 冷却45s → 单发 | 采集器同款请求头 | 200 正常（**排除请求头/UA因素**） |
| 间隔0.6s × 5 | 日K连发 | 3/5 失败 |
| 间隔3.5s × 5 | 日K连发 | 3/5 失败（**失败呈逐请求随机**） |
| 冷却120s → P27全流程 | 快照+日K | 成功；随后第3~4个请求起再度拒连 |
| 冷却150s → 2次抽样 | 日K+快照 | 拒连（期间还出现 ProxyError：**本机系统代理拉起后东财直连更差**，详见 F3） |
| 92.push2his 镜像主机 | 连测4次 | 全部不可用（该编号主机不对外） |

**结论**：push2 系对单 IP 有**每时间窗少量配额**的渐进式限流（估测每 2~3 分钟窗口约 2~4 次成功请求）；超限后先**截断响应体**（实测多处响应在 ~160 字符处被切断），后**直接断连**；冷却后恢复。昨日（10-29）回归中 6 条东财行情词条集中失败、今日 P27 反复失败，均为同一机制，**非采集器缺陷、非持续性故障**。

对候选锚点评估的含义：datacenter / emweb / searchapi 等**财务与检索主机当天全程健康、不受影响**；受影响的仅 push2 行情族。因此"东财作为财务类与备用通道锚点"不受此发现影响；"东财作为行情类唯一锚点"则需要配套健壮化改造（见 §四提案）。

### 候选3：P24 EUR/CNY、P25 GBP/CNY（新浪 → 东财）—— **建议：保留新浪（东财无同口径品种）**

探测证据：`118.EURCNY`、`119.EURCNY` 返回明确"无数据"；searchapi 对"欧元兑人民币"仅返回**外汇期货**（CEU*，MktNum=131），"英镑兑人民币"无结果。东财现货外汇仅覆盖 USD/CNY、USD/CNH 等基本盘，**无 EUR/CNY、GBP/CNY 直盘**。
按不降级原则：迁移需自行交叉算价（口径改变）或降级为期货（口径完全不同），均违反红线2/3。**结论：保留新浪，属②类"有理由的不统一"**，理由（东财无直盘）写入注册表备注。

### 候选4：P26 LME伦铜（新浪 → 东财）—— **建议：保留新浪，列观察项**

## F3 附带发现：桌面系统代理的干扰

限流测试尾段出现 `ProxyError`（环境变量无代理，但 Windows 系统代理被拉起）。系统代理开启时东财直连质量进一步变差，且 `requests` 默认信任系统代理——**采集脚本当前会被动受桌面代理开关影响**。这可能是部分"偶发GET失败"的历史之谜补充解释。
