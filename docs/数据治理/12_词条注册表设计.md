# 词条注册表设计（唯一元数据事实源）

> 数据治理 · 阶段1产出 ｜ 落地文件：`看板数据固化/词条注册表.csv`（阶段2建立并填充）

## 1. 定位

注册表是**运行时元数据的唯一事实源**：看板的单位、小数位、显示窗口、可靠度、口径说明、
数据截至等全部由它派生；改变元数据=改注册表一行+重跑 `生成数据.py`，不再碰任何代码。

与既有文件的关系：
- `数据来源/数据看板-数据来源.xlsx`（台账）= 来源调查档案，人读，**不参与程序运行**；两者以 P 号对齐；
- `固化说明.md` = 使用说明与历史沿革；可靠度/口径以注册表为准，说明文件引用之；
- `docs/数据治理/01_采集器清单矩阵.csv` = 审计快照（阶段0产物），注册表建立后由注册表替代其日常维护职能。

## 2. 字段定义

| 列 | 必填 | 说明 | 派生消费者 |
|---|---|---|---|
| P号 | ✓ | P01…P99 / P201…P234 | 全部 |
| 词条 | ✓ | 中文名（与卡片标题一致） | 溯源索引/日志 |
| 板块 | ✓ | 宏观数据/大宗商品/行业数据/产品品类/竞对同业/资讯 | 溯源索引 |
| 单位 | ✓* | 如 %、点、元/吨、百万台；无量纲留空 | BIND[单位] |
| 小数位 | ✓* | 0-4 | BIND[小数位] |
| 显示窗口 | ✓ | 折线图默认显示最近N点；0=不限制（短序列） | WIN |
| 更新频率 | ✓ | 每日/每周/每月/每季/每次议息/每届 | 卡片foot/新鲜度校验 |
| 可靠度 | ✓ | A/B/C | 卡片角标+溯源索引 |
| 口径说明 | ✓ | ≤60字，悬停展示；如"期货主力口径(历史回填)，数值为现货" | 卡片悬停/溯源索引 |
| 状态 | ✓ | 在板 / 不展示(采集保留) / 入口 / 静态维护 / 受限 | 看板与采集范围 |
| 主键类型 | ✓* | 时序 / 快照 / 面板 / 不适用 | 存储规范适用哪套 |
| 采集通道 | ✓ | 见采集器规范§通道选型 | 审计/维护 |
| 采集器 | 板块 | 文件名或"RPA手册#条目"或"人工" | run_all/维护 |
| 回填策略 | 板块 | latest/full_refresh/incremental_verify/rpa/none | 采集日志 |
| 资讯key | 资讯类 | data-news 锚点键（如 P14、奥海科技公告） | 生成数据.py |
| 备注 | | 特殊约定（如"备注含链接列"） | 维护 |

\* 数值型词条必填；资讯/静态类留空。

## 3. 派生关系（消灭元数据三处分裂）

```
词条注册表.csv
   ├─→ 生成数据.py：BIND = {(P号): (单位,小数位)}；WIN = {(P号): 显示窗口}   ← 不再手写字典
   ├─→ data.js._registry：可靠度/口径说明/更新频率 随数据下发
   ├─→ 看板引擎：卡片角标(A/B/C) 、快报徽标(口径说明含"快报")、溯源索引新增可靠度+口径列
   └─→ 报头"数据截至" = max(各CSV最新数据日期)（阶段4实现，弃用手写文本）
```

## 4. 初始内容来源

阶段2建表时，逐行从以下四处合并（冲突以本表优先级裁决并记录差异）：
1. 《01_采集器清单矩阵.csv》（通道/回填/自动化/可靠度建议）；
2. `生成数据.py` 现行 BIND/WIN（单位/小数位/窗口的现行生效值）；
3. `固化说明.md` 可靠度分级 + 阶段0评级修订提案（8项，已获确认）；
4. 台账 xlsx（词条名/频率/来源网站）。

## 5. 维护规则

- 新增/下线词条：先改注册表，再动采集器/看板；
- 元数据变更（单位/小数位/窗口/评级）：只改注册表 + 重跑 `生成数据.py`；
- 注册表本身纳入存储规范管辖（utf-8-sig、表头变更走迁移流程）。
