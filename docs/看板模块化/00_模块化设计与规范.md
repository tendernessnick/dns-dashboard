# 看板模块化设计与规范（v13 → v14）

> 模块化改造 · 2026-10-29 落地 ｜ v14 视觉迭代 · 2026-10-29 落地 ｜ 上位文档：根目录 `README.md`（现状）、`docs/档案/看板总体设计_v0.1.2_立项档案.md`（立项档案，v19.2整理移入档案区）
> 本文件是「卡片配置 + 布局表 + 渲染器」三层契约的唯一权威定义。改动契约先改这里。

## 1. 背景与目标

v12 实现了「数据与页面分离」（data.js），但卡片仍是 178KB 模板 HTML 里的手写片段：
一张卡的标题、提示、占位文案、脚注、跨列、图表类型、分组位置分散在模板与
`生成数据.py` 的字典里，改一张卡要在多处动刀且可能碰坏邻居。

v13 把**卡片升级为一等公民**：

```
看板骨架.html          页面框架（页头/导航/ticker/附录），长期稳定
   + 布局.csv          板块→分组→行→卡位的唯一顺序表（挪卡、调位置只改这里）
   + 模块/*.json       一卡一配置（改标题/提示/脚注/绑定的P号/卡型只动对应文件）
   + 渲染器/*.js       呈现引擎组件库（改某类卡的渲染行为只改对应文件）
   ───────────────────────────────
   ⇒ 生成看板.py（组装器）→ index.html（页面壳，不含数据）
      生成数据.py（不变） → data.js（数值/资讯/注册表元数据）
```

设计约束（沿袭 v12）：双击即看、离线可用、单文件交付、无构建工具链、
AI 一次会话可独立改任一模块。元数据（单位/小数位/显示窗口/可靠度）**不在卡配置里**——
由数据治理的 `看板数据固化/词条注册表.csv` 唯一驱动（生成数据.py 派生 BIND/WIN/META），
卡配置只管「这张卡长什么样、摆在哪」。

## 2. 布局.csv

列：`序号,类型,引用,跨列,堆叠,容器,代码,隐藏,容器样式,编号,标题,副标题,角标`

| 类型 | 含义 | 关键列 | 说明 |
|---|---|---|---|
| `S` | 板块开始 | 引用=section id(m1…)、编号、标题、副标题、角标(HTML) | 板块按出现顺序取主题色 m1-m5 |
| `G` | 分组标题 | 引用=组名 | 渲染为 `<h3 class="grp">` |
| `R` | 行分隔 | 容器=「卡墙」时本行是 .crow 卡墙 | 行 = 12列grid（.row），卡按跨列排布 |
| `K` | 行内堆叠容器 | 堆叠=组名、跨列、容器样式 | 如 m1「议息双卡」flex c4 竖排两卡 |
| `C` | 卡片位 | 引用=卡片ID(=模块/*.json文件名)、跨列、堆叠、容器=卡墙 | 布局表与卡配置的唯一关联点 |
| `P` | 切换面板 | 引用=公司名、代码、隐藏=是/空 | 首个P行前自动生成 .co-tabs 按钮条 |

规则：
- **加卡** = 模块/ 放入新 JSON + 布局.csv 目标位置插一行 C；
- **挪卡/挪组/换板块** = 只动 C/G 行顺序；主看板跨列沿用卡JSON优先。v22起，页面注册配置`使用布局跨列=true`时，C行跨列只覆盖该页渲染实例，原模块JSON与其他页面不变；
- 行内卡片跨列之和 >12 时 grid 自动换行——但**行边界以 R 行为准**，不要依赖自动流复刻旧版式。

## 3. 模块/*.json（一卡一配置）

文件名 = 卡片ID = 布局.csv 的 C行引用。通用字段：

| 字段 | 说明 |
|---|---|
| `卡名` `标题提示` | card-top 标题与悬停提示；三者全空则不渲染 card-top（strip/hlines 卡） |
| `类型` | 卡型，见下表 |
| `跨列` | 0 表示卡自身不带 cN 类（堆叠卡由容器控宽） |
| `类修饰` | 额外class（kpi/lg/tint/list/strip），原样输出 |
| `主数据` `关联数据` | data-k="2 3 4" 的来源；第一P号决定可靠度角标/溯源锚点 |
| `状态点` `状态说明` | dot g/y 角标（运行时转为文字chip） |
| `卡片样式` | 卡div内联样式（如 min-height:236px） |
| `脚注` | `[{标签:span/a, 文本, href?, target?, rel?, style?}]` |
| `堆叠` `面板` | 所属堆叠组/所属切换面板公司（与布局表呼应） |
| `显示前值变化` | 可选布尔值，默认true；false生成data-change="none"，关闭卡主值及图表/迷你走势的前值差，并使用中性主题线色。用于累计财报、预测等不可直接相减解释的序列。 |
| `显示趋势` | 可选布尔值，默认true；false不输出图表组，并用data-trend="none"阻止自动迷你走势。用于预测与实绩尚未构建可比序列的卡片。 |
| `动态副标题` | 可选文本模板，副标题仍必填作为加载占位；35_bind按主数值最后有效记录替换`{日期}`/`{期间}`(YYYY-MM)/`{年度}`/`{月份}`，与当前数值同时刷新；不支持HTML。 |
| `状态文案` | 可选纯文本状态；静态政策卡设为“静态维护”，由运行时按中性状态显示，不宣称持续核验。 |
| `使用提示` | 可选纯文本，转义后在卡片底部显示口径与解释边界。 |

卡型与专属字段：

| 卡型 | 专属字段（均可选） |
|---|---|
| `kpi` 数值图卡 | `数值占位`(val内HTML)、`副标题`(+`副标题样式`,`副标题在图后`)、`图表组`[{P,列,标题cap,样式,显式列}]、`多品类`(kpi内嵌ul.multi，如P33/P211)、`指标行`[{P,标签,占位,样式}]、`指标行容器样式` |
| `desc` 说明卡 | `说明`(+`说明样式`)、`链接组`[{文本,链接,P}](chips)、`按钮`{文本,链接}、`数值占位`/`副标题`(如P79/P80) |
| `list` 列表卡 | `资讯键`(data-news) 或 `榜单`(data-toplist)+`榜单统计`{P,占位,样式} 或 `时间线`[{下一个,日期,文本}](tl-list) |
| `strip` 汇率横条 | `指标条`[{P,高亮,标签,值占位,说明}]（sc 项） |
| `multi` 多品类卡 | `多品类`、`形态`=列表(ul.multi)/容器(div+data-multi-note)、`容器样式` |
| `share` 份额柱卡 | `份额图`(data-share P号) |
| `ring` 环形卡 | `环形`(data-ring)、`环形文案`{占比,数值,说明}、`环形图`{标签aria,初始占比} |
| `hlines` 展会横排 | `横排`[{P,置顶,链接,点击提示,日期,名称,说明}] |
| `cco` 公司卡墙条目 | `角标字`、`代码`、`说明`、`状态点样式`、`按钮` |
| `planned` 规划预留卡（v23） | `预留编号`（M+模块数字）、`规划对象`：用途/计划内容/使用边界为非空文本，展示字段/候选来源为非空文本列表。卡名及全部规划内容按纯文本转义；原生details展示来源与边界，支持键盘。 |

榜单统计的显示标签由词条注册表“榜单标签”构建为`data-top-label`，优先于历史数据载荷中的标签；修改标签须重建页面，以便在保留旧数据字段的同时正确表达当前口径。

维护规则：
- **改卡只改JSON + 重跑 `python 生成看板.py`**（秒级、确定性重建，其他卡零影响）；
- JSON 手工编辑须保持合法（改完可 `python -c "import json;json.load(open('模块/xxx.json',encoding='utf-8'))"` 自检）；
- 新卡型 = 渲染需求超出既有字段表达力时才新增，须先在本文件登记字段定义。
- `planned`不绑定P号、资讯键、图表、数值、状态点或外部按钮；`主数据`为空、`关联数据`为空数组。生成器拒绝规划卡冒充正式数据卡。预留编号全库唯一并匹配模块数字ID；M编号仅为模块规划编号，P号只在实际接数时登记。
- 页面`PAGE_INFO`的`moduleCount`为总卡数，`activeModuleCount`为已建卡数（含原有受限卡，不代表全部数据可用），`plannedCount`为规划卡数。规划卡不进入PROV或数据源计数；同一预留模块可跨部门复用。
- v23五部门布局与M301—M311清单、升级流程和验收记录见`v23外部情报与部门扩展实施记录.md`。

## 4. 渲染器/*.js

单文件按**文件名顺序**内联进一个 `<script>`（共用作用域，等价于 v12 的单段引擎）：

| 文件 | 职责 |
|---|---|
| 00_core.js | 根节点、BIND/WIN/PSEL、wind()、escH/fmtN/fmtT/getSeries（纯依赖，无DOM副作用） |
| 05_news.js | 资讯/公告feed注入（data-news）+ 空feed兜底提示（v14：日期chip） |
| 10_theme.js | 板块主题色（--acc） |
| 15_chart.js | 交互折线图（.chart[data-chart]；v14行情风：区间涨跌红绿/渐变面积/期初基准虚线/尾点呼吸圈/最新价chip/描画动画，小图自动精简） |
| 17_spark.js | v14新增：KPI卡迷你走势（无图表组且序列≥3点时自动注入 .sparkrow，免卡配置） |
| 20_share.js | 品牌份额分组柱状图（.sharechart[data-share]） |
| 25_resize.js | 窗口resize重绘（v14：折线重绘不重播动画） |
| 30_multi.js | 多品类行/横条（data-multi；v14：单位列启发式——列名含%显示%、含样本/数量不标单位） |
| 35_bind.js | 数值绑定（.val卡片/.sc/ticker/statline；v14：大数字滚动动画、涨跌chip带▲▼与固定小数、.sc较前值chip） |
| 40_copanel.js | 上市公司切换面板 |
| 45_period.js | 全局周期选择器 |
| 50_governance.js | 数据截至/可靠度角标/快报徽标/待补录标注（读注册表元数据） |
| 55_ring.js | Qi2环形图（v14：品牌蓝定妆 + 圆弧生长动画 + 占比滚动，REDUCE降级） |
| 60_toplist.js | Amazon榜单快照（v14：名次徽章金银铜/价格chip/Anker高亮） |
| 62_feedfade.js | v14新增：滚动feed底部渐隐提示（溢出时渐隐、滚到底消失） |
| 65_nav.js | 导航高亮 + 回顶 + 外链卡片委托点击（v18.7：hlines 卡 data-href 属性统一在此打开，组装器不再注入内联onclick） |

约定：渲染器只读 `DDATA/BIND/WIN/NEWS/TOPS/META/PEND/ASOF`（data.js 下发），
禁止直改卡片静态文案；卡片静态内容由组装器的 builder 从 JSON 生成。
引擎与页面通过 data-* 属性锚定（data-k/data-chart/data-news/…），与卡壳解耦。

## 5. 与数据治理的边界

| 关注点 | 唯一事实源 | 生效方式 |
|---|---|---|
| 数值/序列 | 看板数据固化/CSV数据/*.json | run_all.py 采集 → 生成数据.py |
| 资讯/公告/榜单 | 资讯数据/*.json | 同上 |
| 单位/小数位/窗口/可靠度/口径/频率 | `词条注册表.csv` | 改注册表 → 生成数据.py → 刷新 |
| 卡片呈现（标题/脚注/卡型/跨列） | `模块/*.json` | 改JSON → 生成看板.py |
| 卡片位置（板块/分组/顺序） | `布局.csv` | 改CSV → 生成看板.py |
| 来源溯源（附录表/tooltip） | `看板数据固化/溯源表.csv` | 改溯源条目 → 生成看板.py 注入骨架（v17落地治理遗留#4，骨架内嵌PROV已移除） |
