## 一、目标

1. 逐模块盘点当前采集通道的可靠性，识别"爬虫不可靠 / 无API / 受限"的词条；
2. 为其寻找更优的单一数据源或免费API（akshare 类），按**不降级原则**（第二期红线：可靠度/历史深度/及时性/口径四维不劣于现源）验证后迁移；
3. 对确实只能浏览器获取的受限模块，产出 **AutoGLM（Edge插件）RPA 任务提示词**与落盘规范；
4. 建立**定时任务**：每日自动采集→验证→推送 GitHub（有变化才推）；每周巡检；
5. 本期成果验证后推送 GitHub，并更新 CloudBase 静态站。

## 二、内部质量红线（沿用，自行把关并全程留痕）

1. 不丢一行历史数据；CSV 写改前备份 + 零丢失校验；
2. 不改业务口径：候选源口径不一致即不迁移，记"保留现状+理由"；
3. 不降级原则：四维对比有一项明显劣化即放弃；
4. 采集逻辑最小侵入：优先改采集器内部取数函数，CSV 表头与 save_row 流程不变；
5. 用户已下放逐项确认权，但**每个迁移项必须在 diff 报告中留痕**（动机/证据/回滚方式）；
6. 东财 push2 限流规则（02报告F1）继续生效：退避重试、组间间隔不得回退。
