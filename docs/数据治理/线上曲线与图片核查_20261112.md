# 线上曲线与图片核查

日期：2026-11-12。核查对象为用户提供的CloudBase数据看板站点，基于当次实际HTTP响应、浏览器运行及本地固化数据；不以Git推送成功或旧定时任务日志代替线上验收。

## 结论

1. **确认线上媒体增量漏同步。** 当前data.js引用36张本地图文图片，其中20个线上对象是有效JPEG且与本地字节一致，16个返回`200 text/html`，内容实际为既有个人主页的404兜底页（1967字节）。它们不是有效图片，不能因HTTP状态为200判为发布成功。
2. **没有复现数值曲线丢失。** 74项数值数据、7481行与原CSV逐行逐列一致；v25与v26数值载荷一致。线上五页及战略、市场各五家公司的切换共15个状态中，有效折线均存在、坐标无NaN、SVG尺寸正常，没有可见`.chart .nodata`。各页当前可见趋势数量为32/7/1/8/0，人力页没有配置数值趋势。
3. **前端存在误导提示。** 原图文error处理把缺对象/网络加载失败也写成“图片待核对”。该文案应仅用于明确待核对的配图，已在本地修复；精选图片同时增加加载失败兜底，原文链接保持可用。

## 发布断层的证据

五份页面和data.js与本地d22a1fd版本在统一UTF-8与换行后内容一致。所有16个异常图片引用都不在上次成功发布对应的f89da3a媒体清单中，而20个正常图片引用全部在旧清单中。这支持“页面和数据更新了，媒体增量未同步”的判断；个人404标题本身不能证明整个站点部署到了错误环境。

本地最近批量采集记录中的P22失败未删历史，其数据仍保留；P34/P35为已停显后台采集项。预测、单期快照与规划卡不应因为没有趋势被解释为历史丢失。
