# 任务指令书 · 数据治理第二期：数据来源归一化治理（草稿，待用户审阅）

## 〇、角色与授权

你是本项目的数据治理工程师（第二期任务）。项目已于 2026-10-28 ~ 10-29 完成第一期五阶段数据治理（报告见 `docs/数据治理/06_数据治理总结报告.md`）：建立了词条注册表（`看板数据固化/词条注册表.csv`，108 词条）、三份规范（10 采集器 / 11 存储 / 12 注册表），统一了 save_row、schema 保护、run_collector、采集日志等基础设施，并通过零丢失回归验收。**第一期成果是本期的地基，本期不得破坏第一期已建立的任何结构与规范。**

本期治理对象：**数据来源层面的"同域不同源"分散问题**。

## 一、问题描述

现状：部分相关指标（同一数据域内的词条）由不同网站/接口分别供给——例如同一看板分区里的几个金属价格各来自不同站点、同属"宏观-美国"的几个指标分别来自 FRED / 东财 / TradingEconomics——尽管其中某一家可靠站点有能力同时覆盖域内多个词条。

危害：同域数据难以交叉验证；单源失效时同域备用源不清；看板同区卡片来源标注杂乱，可信观感受损。

必须区分三类"不统一"，本期只处理第一类：

| 类型 | 定义 | 处理方式 |
| --- | --- | --- |
| ① 可归并的不统一 | 同域多词条可被同一可靠站点的不同板块覆盖，现源只是历史沿革凑合 | **本期对象**：评估统一 |
| ② 有理由的不统一 | 口径不同（如美国 PMI 的 ISM 口径 vs S&P Global 口径）、历史深度悬殊、更新频率错位 | 保留现状，在注册表"口径说明/备注"写明理由 |
| ③ 必然的不统一 | 独占数据（IDC 出货量、安克官网动态、巨潮公告原文、生意社报价动态原文等） | 保留，标注"独占源" |

## 二、治理目标

1. 产出全部 108 词条的**相似性分组**：按数据事实域聚类（不是按现有看板板块机械照搬），形成"来源域地图"。
2. 对每个域完成**同源覆盖审计**：域内哪些词条存在"可用同一站点"的机会，候选统一站点是谁，四维对比如何。
3. 产出**决策矩阵并获逐项批准**后实施迁移，使尽可能多的域达到本项目已验证的统一标杆形态——生意社（P28/P39/P40 共用 `ppi_100ppi.py` 解析器）与 Eurostat（P08/P10/P12/P13 共用 `estat_series_merge`）即为现成的"统一形态"参照。
4. 迁移后全量回归，确保：迁移项数据质量不降级；未迁移项零变化。

## 三、硬约束（红线，全程有效，违反任意一条即视为任务失败）

1. **不丢一行历史数据**：任何 CSV 写改前先备份；沿用第一期零丢失校验方法。
2. **不改业务口径**：统一来源 ≠ 统一口径。候选源与现源口径不一致的，一律按②类"有理由的不统一"保留，不得为统一而换口径。
3. **不降级原则（本期核心红线）**：任何迁移必须证明候选源在【可靠度 / 历史深度 / 更新及时性 / 口径一致性】四项上**均不劣于**现源；任何一项明显劣化即放弃迁移，结论记"保留现状"并附证据。**宁可少统一，不可降质量**——局部强行关联拖垮整体数据质量，是本期明令禁止的失败模式。
4. **历史不拼接**：切换源默认采用"新源自切换日起接管，历史保留原源"策略；仅当新源支持全历史回填、且抽样对比（≥3 个数据点，含最近数据日）偏差在精度容忍内，才允许全量替换。任何日期不允许出现两行并存。
5. **采集逻辑最小侵入**：优先改造现有采集器内部的取数函数，CSV 表头与 save_row 流程不变；≥3 个词条共用新站点时才新建公共 helper（`ppi_100ppi.py` 模式）。**动任何采集逻辑前逐条列影响清单，经我确认后执行。**
6. **分阶段推进**：每阶段产出报告后停下等我确认，确认后才进下一阶段。
7. **危险操作前必须列影响清单**：删文件、批量改写历史、重命名/迁移文件，先列清单待批。
8. **降级链要求**：每个完成统一的域，必须在注册表"备注"注明至少一个备用数据通道，防止单点故障。
9. **与第一期遗留项解耦**：P46 抓旧稿、P06 备注覆盖等第一期遗留项维持"待批"状态，本期不顺手修改。

## 四、执行阶段（五阶段，每阶段一道确认门）

### 阶段 A：模块相似性组织（纯只读）
- 以 `词条注册表.csv` 108 词条为底，按**数据事实域**聚类（预计域如：宏观-美国、宏观-欧洲、宏观-中国、汇率、金属-铜、金属-锡铝、塑料原料、半导体存储、半导体行情、出货量-全球、出货量-中国、品牌竞对财务、电商零售、资讯流等，以实际分析为准，可增删合并）。
- 每域登记：词条号、当前源（站点+接口）、采集器文件、历史深度、更新频率、可靠度评级（沿用第一期 A/B/C）、近期日志成功率（从 `采集日志.csv` 统计）。
- 产出：`00_模块相似性分组表.csv` + `01_阶段A报告.md`。**停下待确认。**

### 阶段 B：同源覆盖审计（只读 + 在线探测）
- 对每个域考察 2~4 家候选统一站点：能否同站覆盖域内多词条？走哪个板块/接口？口径是否一致？历史深度与更新频率？站点稳定性（结合日志中该站历史失败记录，如东财 kline 间歇失败、Cloudflare 403 等）。
- **在线实测**：候选站点与现源抽样对比 ≥3 个数据点（含最近一个数据日），量化偏差（绝对值+相对值），写入对比矩阵。只探测、不写任何项目数据文件。
- 每域给出初步结论方向：完全统一 / 部分统一 / 保留现状 / 观察项。
- 产出：`02_同源覆盖审计报告.md`（含对比矩阵与偏差数值）。**停下待确认。**

### 阶段 C：决策矩阵（逐项审批）
- 全部候选迁移项汇成决策矩阵：四维对比结论 + 抽样偏差 + 实施方式（改造哪个采集器 / 是否新建 helper）+ 接管策略（新源接管 or 全量回填替换）+ 风险与回滚方案。
- 每项标注建议：**统一迁移 / 保留现状（附理由）/ 观察项**。域内允许部分统一：能安全统一的子集迁移，会劣化的词条明确标注"独立源（有理由）"。
- 产出：`03_来源归一决策矩阵.csv`。**我逐项批注（同意/否决/改观察）后，你只实施"同意"项。**

### 阶段 D：批准项实施（最小侵入）
- 逐项实施：备份目标 CSV → 按批准的接管策略改采集器 → 试运行 → 数据校验（历史零丢失 + 新源行数/日期连续性）。
- 同步更新注册表相应列（采集通道/采集器/口径说明/备注）；如需为注册表加列（如"来源域ID""备用通道"），在决策矩阵中一并提出，经批准后加列，**不删不改既有列**。
- 产出：`04_阶段D迁移diff报告.md`。**停下待确认。**

### 阶段 E：回归验收与总结
- `run_all.py` 全量回归：迁移项前后成功率与数据量对比；**未迁移项必须与基线完全一致（零变化）**。
- 重新生成 data.js 与看板，抽验同域卡片来源标注的呈现效果。
- 产出：`05_来源归一治理总结报告.md`（统一前后来源地图、迁移清单、遗留项）。
