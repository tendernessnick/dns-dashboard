## 1. 定位与目标

- **产物形态**：美观的本地静态 HTML 数据看板，不上线部署；当前供部门内部查看，优化到可用程度后可能转发全公司，**呈现质量以"可向董事会讲解"为标准**。
- **核心目标**（按优先级）：
  1. **数据复用最大化**：一份数据、一张图，多处引用；图表是独立资产，页面只是引用者。
  2. **更新成本最小化**：模块独立更新，AI 更新时只动对应模块的数据与图表，不做无关工作。
  3. **呈现可讲解**：版式、配色、图表风格统一，重点突出，能支撑口头汇报。
- **与数据积累的关系**：看板是数据资料的"展示壳"，不反向修改资料库；资料库（双处归档 + 索引）始终是唯一事实源。

## 2. 总体结构：「1 + 5」多页 + 综合

- **页面清单**（对齐第 6 节五大信息板块）：

| 页面 | 文件名（暂定） | 内容 |
| --- | --- | --- |
| 综合看板（首页） | `index.html` | 各板块核心指标速览 + 精选图表 + 数据新鲜度状态，详见第 6 节 |
| 宏观页 | `macro.html` | 宏观经济、行业总量、半导体、进出口、政策、权威预测 |
| 大宗商品页 | `commodity.html` | 汇率、铜价、半导体行情、锂电产业链、塑料原料等成本侧数据 |
| 行业页 | `industry.html` | 出货量、竞争格局、渠道、供应链、行业研究 |
| 产品页 | `product.html` | 评测、BOM、价格、销量排行、认证、新品前瞻 |
| 竞对页 | `competitor.html` | 竞对财务、份额、产品线、供应链情报、舆情热度 |

- **拆页规则**：单板块内容放不下时拆为多页，命名 `<板块>-<子主题>`（如 `macro-cn.html` 宏观-中国、`macro-global.html` 宏观-全球）；拆分以"子主题内图表能同屏讲一个故事"为准，宁多页勿超长页。
- **导航**：所有页面共用顶部导航栏（综合 / 宏观 / 大宗商品 / 行业 / 产品 / 竞对），样式由统一 CSS 文件控制。

## 3. 模块化机制（核心设计）

### 3.1 模块定义

**模块 = 同一更新频率、同一主题的一组图表/指标的展示单元**，是看板更新与复用的最小单位。例如「全球 TWS 出货量（季度）」「中国 GDP 与消费信心（月度）」各为一个模块。

- 模块按更新频率分层：**周更 / 月更 / 季更 / 半年更 / 长期静态**（长期静态图跨期复用，仅来源数据换代时才换）。
- 各模块独立更新、互不影响：更新月更模块不触碰周更模块的任何文件。

### 3.2 三层解耦

```
数据层（资料库 xlsx，双处归档，带日期命名，保留历史序列）
   ↓ 单来源出图（第 8 节规范，图表与源数据同名）
图表层（png，归档在各项目「图表」文件夹，同样带日期命名）
   ↓ 以固定文件名复制一份到看板站点目录
展示层（HTML 以固定文件名引用图表，页面结构长期稳定）
```

- **「当前版图层」机制（复用最大化的关键）**：看板站点目录内为每个模块维护一个**固定文件名**的当前版图表（如 `assets/charts/行业_TWS耳机全球出货量.png`）。每次数据更新后，将新生成的带日期图表**复制替换**该固定文件——**HTML 页面零改动**。
- 原始归档**不覆盖、不删除**（第 7.3 节历史序列规则不变）；固定文件名副本仅存在于展示层，属展示行为，不违反历史保留规则。
- 数据更新日历、图表版本等信息以页面文字标注（数据日期、制图日期本就在图表标注四要素内）。

### 3.3 模块登记表（建板时建立）

- 以 `看板模块登记表.md`（后续视情况转 xlsx）登记全部模块，字段：**模块ID、所属页面、板块、更新频率、数据来源、当前版数据文件、当前版图表文件、备注**。
- 该表是 AI 更新看板的**唯一定位入口**：更新任务下发后，AI 按表找到待更新模块 → 采集/取数 → 出图 → 替换当前版文件 → 更新表内登记，全程不触碰其他模块。
- 模块登记表本身放本文件夹，随看板演进维护。

## 4. 对数据采集的前置要求（与 AGENTS.md 第 9 节呼应）

看板能否低成本建起来，取决于前期数据是否按以下要求前置处理（大部分已是现行规范，此处汇总为看板视角的检查单）：

| 前置要求 | 依据 | 对看板的意义 |
| --- | --- | --- |
| 命名规范 `YYYYMMDD_来源_颗粒度_主题` | 第 7.3 节 | 同主题文件天然构成时间序列，模块可直接取用 |
| 索引备注注明更新频率 | 第 7.4 节 | 模块按频率分层直接映射，无需逐个判断 |
| 实际颗粒度如实标注 | 第 5 节 | 页面展示时口径可信，综合看板整合不出错 |
| 图表标注四要素（来源/口径/数据日期/制图日期） | 第 8 节第 2 条 | 图表放进看板即自带说明，无需二次加工 |
| 仅单一来源出图、AI 不整合数据 | 第 8 节第 3 条 | 每个模块口径单一、可溯源；整合留给标准化流程 |
| 数据覆盖**多样、完整、准确** | 综合看板需要 | 板块覆盖越广、口径越清晰，综合看板可选素材越多 |

## 5. 页面布局构思（早期）

### 5.1 通用页面骨架

```
┌─────────────────────────────────────────┐
│ 顶部导航：综合 | 宏观 | 大宗商品 | 行业 | 产品 | 竞对 │
├─────────────────────────────────────────┤
│ 页头：页面标题 + 本页最近更新日期                      │
├─────────────────────────────────────────┤
│ KPI 行（可选）：3–5 张核心指标卡片                  │
├─────────────────────────────────────────┤
│ 图表网格：按子主题分区排布（每区一个小标题）            │
│  ┌────────┐ ┌────────┐ ┌────────┐        │
│  │ 图表模块 │ │ 图表模块 │ │ 图表模块 │        │
│  └────────┘ └────────┘ └────────┘        │
├─────────────────────────────────────────┤
│ 页脚：数据说明（仅供内部使用、口径与溯源见索引.md）      │
└─────────────────────────────────────────┘
```

- **排布原则**：更新频率高的放上方（越常看越靠前）；同一子主题/同一口径的图表同区；一屏重点不超过 3–5 个，宁留白勿堆砌。
- 每张图表下方保留一行小字：来源机构 + 数据日期（图表内已标注的在此不必重复，仅做补充说明）。

### 5.2 综合看板（首页）定位

- **v1 定位：精选 + 状态，而非深度整合**。内容三块：
  1. **核心指标卡片区**：五大板块各挑 1–2 个最有信号量的指标（如全球消费电子出货量、铜价现货、TWS 份额、竞对最新季收）。
  2. **各板块精选图表**：每板块 1–2 张代表图，直接复用板块页的当前版图表文件。
  3. **数据新鲜度看板**：按模块列出各板块数据最近更新日期与更新频率，一眼看出哪些数据该更新了——同时充当采集任务的"待更新提醒器"。
- **整合升级留待阶段三**（第 8 节路线）：真正的跨来源整合指标（如四大品类市场空间测算）等标准化整合流程建成后上综合看板；**在此之前综合看板不做任何数据整合**，避免违反第 8 节数据质量红线。

## 6. 数据展示方式（早期方向，待子文件细化）

- **KPI 卡片**：指标名 + 数值 + 环比/同比箭头 + 数据日期 + 来源；数值变化用语义色（涨/跌），颜色含义全站统一。
- **图表类型选型原则**：时间序列 → 折线/柱状；份额结构 → 堆叠柱/环形；多对象对比 → 分组柱状；单期构成 → 饼图慎用（类别多时用条形）。
- 图表内文字（标题、标注、图例）字号、字体全站统一；预测值沿用现有惯例（琥珀色/虚线区分，见 README 第 5 节）。
- 详细规范（配色值、字号、尺寸、边距、标注样式）由子文件《图表设计规范》承载。

## 7. 视觉与技术形态（早期）

- **技术形态**：纯静态 HTML + 共用 CSS（+ 少量 JS），图表以 `<img>` 引用 png 为主（与当前产物形态一致）；无需构建工具链。
- **交互**：v1 以静态呈现为主（页面跳转 + 锚点目录即可）；ECharts 内嵌交互属于可选升级，待静态版稳定后评估，避免过早引入复杂度。
- **视觉风格**：商务简洁、克制用色；单主题先行（浅色或深色择一，待用户定）；中文字体清晰易读、数字对齐。详细规范由子文件《视觉风格规范》承载。
- **文件组织**（看板站点目录，建板时创建，暂定放本文件夹下 `dashboard/` 子目录）：

```
数据看板构建/
├── 看板总体设计.md            # 本文件（总纲）
├── 看板模块登记表.md          # 模块与文件映射（建板填充时建立）
├── <各子规范文件>.md          # 图表/排版/数据展示/视觉风格/更新流程（见第 9 节）
└── dashboard/                # 看板站点目录（空模版 v1 已建，无任何数据）
    ├── README.md             # 空位编号规则与后续填充方式
    ├── index.html  macro.html  commodity.html  industry.html  product.html  competitor.html
    ├── style.css             # 全站统一样式
    └── assets/charts/        # 各模块当前版图表（固定文件名副本，填充后启用）
```
