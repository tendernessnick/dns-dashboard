# 采集器开发规范

> 数据治理 · 阶段1产出 ｜ 生效日期 2026-10-28 ｜ 适用 `看板数据固化/采集脚本/` 全部采集器及后续新增
> 本规范经确认后于阶段3落地执行；落地前现有采集器按现状运行。

## 1. 总则

1. **一个词条一个负责通道**：每个 P 号有且仅有一个采集责任方（脚本采集器 / RPA / 静态人工），登记在《词条注册表》。禁止无登记的旁路写入。
2. **采集器只生产数据，不碰展示**：输出唯一落点为 `CSV数据/`（数值）与 `资讯数据/`（资讯JSON）；禁止采集器直接修改看板 HTML/data.js。
3. **历史数据只增不删**：采集器永远通过 `save_row`（按主键 upsert）写入；禁止整文件重写历史行、禁止按"今天有新值"删除旧行。
4. **失败宁可空缺，不可编造**：抓取失败必须如实记录并返回失败；禁止以估算值、旧值、猜测值补位。

## 2. 统一骨架（阶段3由 common.run_collector 落地）

每个采集器必须暴露：

```python

PID = 26                      # P号（int）
TITLE = 'LME铜'               # 词条名（与注册表一致）
BACKFILL = 'latest'           # 回填策略声明，见 §4

def run():
    """返回 (状态, 详情)；状态 ∈ 成功/失败/跳过；详情为一句话结果（≤300字）。"""
```

阶段3起 run_all 通过统一包装器调用 run()，自动完成：计时、异常捕获（未捕获异常记为失败）、
log_result 落日志（含 run_id/耗时/回填策略）、单采集器超时（默认 180s，超时记失败）。
采集器内部不再各自 print 汇总，统一以返回值表达。

## 3. HTTP 与解析标准

| 项 | 标准 |
|---|---|
| 请求 | 一律经 `common.http_get/http_post`（自带 UA/重试/编码）；默认 timeout=25s、retries=2，不得低于此配置 |
| 反爬 | JS 验证墙用 `curl_cffi`（impersonate='chrome'）；**禁止**伪造 Referer 绕过登录墙 |
| 会话 | 登录墙源（富宝/企查查/H10/Keepa）不在脚本内处理凭据，走 RPA（见 §6） |
| 解析 | 正则必须锚定上下文（禁止裸数字匹配）；解析失败=失败，不得留半行数据 |
| 数值 | 写入前做量级区间校验（每采集器声明 RANGE），越界视为失败 |
| 日期 | 一律经 `common.parse_date_label` 规范化为 YYYY-MM-DD（期末口径） |

## 4. 回填策略声明（BACKFILL 枚举）

| 取值 | 语义 | 现状词条示例 |
|---|---|---|
| `latest` | 只写最新一期，历史靠逐日积累 | P21-P27、P36-P40 行情类 |
| `full_refresh` | 每次运行重刷全量历史（官方API类，幂等） | P01、P08、P10、P12、P13 |
| `incremental_verify` | 增量爬源文章/新闻稿回填考证（按主键去重，只补缺失） | P33；P46/P48 的缺季检测归属此类 |
| `rpa` | 浏览器 RPA 落地，脚本侧无采集器 | P07/P28/P53/P70/P73/P76/P77/P83/P98/P99 |
| `none` | 不适用（静态/入口） | P16-P20、P50/P51 |

**选择原则**：源提供全量序列 API → `full_refresh`；源只能逐篇回看 → `incremental_verify`；
源只给最新值 → `latest`。禁止在一个采集器内混用两种策略而不声明。

## 5. 异常与降级语义

1. 首选通道失败且存在备选通道（如富宝→长江、ECB→Eurostat）：自动降级并在**备注注明实际通道与原因**，返回成功。
2. 无备选通道：返回失败，详情含可定位的原因（HTTP码/解析锚点缺失），禁止静默成功。
3. 快报/占位机制（闪估值先行）：备注必须含"快报"字样，注册表可靠度标注"含快报占位"；正式值到达后由下次运行覆盖。
4. 代理口径（如生意社基准价代理无氧铜杆）：备注必须含"代理口径"字样。

## 6. RPA 与脚本的边界

- **走脚本**：公开页面/公开API/仅需反爬伪装的源。
- **走 RPA**：登录墙（需账号会话）、强 JS 渲染且无接口、平台风控严格（企查查）。
- RPA 条目必须：①提示词收录 `RPA任务提示词.md`（工作区相对路径+锚点校验）；②写出的 CSV 与脚本采集**同 schema 同规范**；
  ③在注册表标注 `rpa` 回填策略与提示词条目号；④连续失败 3 次触发人工复核（人工检查来源是否改版）。
- 已脚本化的条目不得保留双轨（案例：P12 已 Eurostat 全自动，RPA 手册中 P12 条目应标记废弃）。

## 7. 新增采集器 checklist

- [ ] 注册表新增行（P号/词条/通道/频率/单位/可靠度）
- [ ] 文件名 `collect_P{序号}_{中文名}.py`；暴露 PID/TITLE/BACKFILL/run()
- [ ] CSV 遵循《固化数据存储规范》（对应 schema 类型）
- [ ] 量级校验 RANGE；日期经 parse_date_label；来源措辞符合标准
- [ ] `python run_all.py P{序号}` 单跑通过；采集日志出现本次记录
- [ ] RPA 条目另：提示词入手册
