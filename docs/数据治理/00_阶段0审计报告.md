## 二、问题清单（按严重度分级）

### P0 —— 数据正确性风险（会静默产生错误数据或丢数据）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| P0-1 | 归档文件与在用数据同目录，读取靠文件名排序运气 | `产品品类-P72-价格带结构-旧口径存档.csv` 与正式文件同在 CSV数据/；生成数据.py 无显式排除规则 | 新增/重命名文件即可让看板读错口径 |
| P0-2 | `save_row` 表头变更即清空全表历史 | common.py L90-91：fieldnames 不匹配 → rows=[]；无 schema 保护 | 任一采集器改列而未人工迁移，历史瞬间清零（v8 已发生过） |
| P0-3 | 考证型条目无补录机制 | P46/P48 采集器只抓最新稿；2024Q3/Q4、2025Q3 等 6 个季度靠人工考证写入；IDC 发布 2026Q3 后无人补录 | 缺口静默扩大；采集器未来若抓到不同口径稿会与人工行冲突 |
| P0-4 | 报头"数据截至"为模板手写静态文本 | 看板模板 L290 固定 `2026-10-23`，现已过期 | 看板声明的数据时点失真，汇报场景是硬伤 |
| P0-5 | 非词条数据混放固化目录 | `交叉验证-行情双源对照.csv` 无数据日期/来源/备注列（运行日志性质），与词条CSV同目录 | 目录语义不纯；侥幸未被 load_data 误读 |

### P1 —— 规范化债（影响维护效率与数据可信度）

| # | 问题 | 证据 |
|---|---|---|
| P1-1 | 单位元数据三处分裂 | CSV单位列(23个文件) / 生成数据.py BIND字典(硬编码) / 模板卡片静态文字，三处可互相矛盾且无一致性校验 |
| P1-2 | CSV schema 离散 | 12 种列结构；来源措辞 50 个文件超长（如含括号长描述）；5 个文件备注当URL字段用；备注列语义无定义 |
| P1-3 | 采集器外壳不统一 | 异常处理/超时/重试各异；回填策略无声明（读代码才能知道）；仅约定 run() 返回值 |
| P1-4 | run_all.py 无单条目超时 | 单采集器挂起会阻塞整批；失败仅打印无分级落盘 |
| P1-5 | 采集日志信息不足 | 无 run_id、无耗时、详情自由格式，无法回答"这批数据是哪次运行产的" |
| P1-6 | 资讯JSON字段不齐 | title_zh 仅翻译覆盖源有；kickstarter/摩点 items 字段与其他源不一致 |
| P1-7 | 可靠度在看板不可见 | A级双源核验与C级单源解析同等呈现；快报值(P08/P13)与正式值卡面无区分 |
| P1-8 | 可靠度分级已过时 | 固化说明的 A/B/C 未随 v11 更新：P08/P10/P12/P13 应升A（官方API全历史）；P11 应降C（TE镜像）；P46/P48 应降C（含推算行）；P33 新增未评级 |
