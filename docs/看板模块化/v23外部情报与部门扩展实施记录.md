# v23 外部情报与部门扩展实施记录

日期：2026-11-12。本轮目标：回应战略经理视角的九项质疑，明确既有指标的解释边界；为设计、产品、人力部门增加外部情报视图，并预留十一项后续能力。

本轮**不开展新数据采集**。新增的是页面组合、规划模块及其展示契约，不是已接通的新数据源。五页与离线分享版的已完成功能及上轮验收记录见文末；本次仅将规划编号与模块数字ID顺接到既有序列。

## 一、范围与状态口径

- 仅使用外部公开信息：官方统计与公告、公开财报、公开商品页面、标准与认证资料、公开拆解评测、公开用户反馈、公开招聘和薪酬说明等。
- 不引入公司内部BOM、采购合同、订单、经营预算、产品研发文件、员工薪资、考勤或个人履历；不建立个人离职意愿、绩效或任职风险评分。
- 原有已建模块继续复用同一份JSON、渲染器、`data.js`和媒体，不为各部门复制业务数据。
- 新增十一份`planned`模块只显示用途、计划内容、展示字段、候选公开来源和使用边界。候选来源是后续研究方向，**尚未完成可采性、稳定性和口径核验**。
- 页头区分“已建模块”与“规划模块”。“已建”表示模块已存在，不等于全部已自动接入；其中受限入口、静态维护和真实空态继续保留各自状态。
- 部门页面用于切换阅读视角，共享客户端载荷，不提供部门权限隔离。

十一项新增规划条目沿用历史P号习惯，并按既有最大模块号254顺延为P255—P265；对应JSON的数字ID和文件名前缀统一为255~265，布局引用同步调整。原有P号和旧模块保持不变，规划状态仍为planned，主数据仍为空，尚未开展采集或正式来源注册。编号与规划状态分开管理，既有功能和数据统计规则保持不变。

## 五、以后如何将planned升级为正式模块

1. **确认问题与最小样本。** 从卡片用途选择一项明确决策，定义最小展示字段、更新频率和可接受的数据滞后；先用可核对的公开人工样本验证。不得填入示例数值冒充真实结果。
2. **核验实际来源。** 逐一核对原文内容、发布时间、观测期、地区、单位、币种、实际/预测、累计/单季及样本范围。候选网站可访问、品牌有新闻或职位页存在，都不等于已有可用数据。
3. **优先复用已注册数据。** 能从既有P号形成模块时，声明真实依赖并保留原口径；需要派生结论时，记录算法、阈值、局限和原始证据。不要为了部门视图复制同一份采集结果。
4. **接数时正式登记预留P号。** 按`docs/数据治理/10_采集器开发规范.md`、`11_固化数据存储规范.md`和`12_词条注册表设计.md`确认采集与存储契约；查重后，在词条注册表和溯源表正式登记对应的预留P号、来源、单位、频率、主数值列、可靠度、时效与核验方式。资讯或图文还须登记实际文件、资讯键或图文目录；不得占用已有P号或虚构未核验来源。
5. **保存可审计的真实数据。** 数值CSV按现有日期及主键规范落库；资讯保留原文链接、发布与采集时间；招聘按公司、岗位族和地区汇总并去重。表头变化走迁移，保持历史零丢失，不直接覆盖旧口径。
6. **实现异常与缺失状态。** 区分无新增、无可展示内容、源受限、请求失败和数据过期；不得以空值代替零，不以“脚本没报错”代替数据新鲜或来源准确。
7. **更换正式卡型。** 根据真实载荷将`类型`改为已有的`kpi/list/review/multi`等合适卡型，移除规划专用字段和占位状态，设置真实主数据、关联数据及来源依赖。只有实际接入并完成核验后才调整状态文案。
8. **验收后进入日常更新。** 完成离线样本与异常回归、数据对照、五页复用、手机布局、溯源回跳和单文件离线验证；再决定是否将已验证采集器加入调度。保留预留P号从planned到正式登记、实际数据绑定及状态变更的记录，方便审计。

以上为后续接入流程，本轮仅预留P255—P265，没有执行新的来源采集、正式P号注册或正式模块升级。
