## 架构与配置契约

`看板/页面.json`登记视图，`页面配置.py`在构建时验证ID、输出名、布局存在性及字段类型。页面都位于看板同目录，避免本地`file://`的跨目录媒体和fetch限制。

每页配置包含：

| 字段 | 含义 |
|---|---|
| ID | 小写英文ID，例如marketing；不可重复 |
| 名称 / 文件 | 顶部按钮文案与同目录英文HTML输出名 |
| 布局 | 同目录CSV，沿用原S/G/R/K/C/P结构 |
| 标题 / 副标题 / 眉标 / 定位 / 说明 | 页面文字，构建时转义，不写入业务模块 |
| 使用布局跨列 | true时用本页C行跨列覆盖渲染实例；原模块JSON与其他页面不变 |
| 速览 | 是否保留原主看板的6指标摘要；市场页关闭，直接进入新品情报 |

新增部门的操作：

1. 复制`布局_市场部.csv`为新部门布局，按工作流修改S/G/R/P及C模块引用。每页模块引用须唯一且已存在；跨列1~12，普通行建议合计12列。
2. 在`页面.json`增加配置，并保持“默认页面”引用存在的ID。现有主看板配置不需要改。
3. 运行`python 看板/生成看板.py`，一次构建所有视图；再运行`python 看板/打包单文件.py`。
4. 本地检查新页面及分享版。部署普通页面时上传所有登记HTML、共享data.js与媒体；页面注册JSON和Python不需要给浏览器运行。

## 复用过程中修正的边界

- 卡片实例ID与数据P号分离，内部指标不再重复创建`card-P…`；同P多卡不会撞ID。
- 每张卡记录来源依赖。依赖包含主P、关联P、图表/嵌套指标及资讯键对应注册表P号；空主数据的互动模块也能进入溯源。
- 附录回跳优先当前可见卡；目标藏在公司面板内时先切换公司，再滚动定位。来源数据不是DOM实例标识。
- 公司切换限制在所属板块，不会隐藏另一个公司分组；公司按钮组ID按板块生成。
- 片内导航由本页S行生成，部门切换放独立导航区，避免把`marketing.html`当作CSS选择器。
- 普通页面共享同一份data.js，仍保留源数据时间、累计/预测和原渲染规则。

## 单文件分享

分享版内嵌一次共享数据及图文媒体，以及各页源码；切换时用一个iframe按需装入对应文档，隔离固定ID和全局JavaScript。顶部部门链接改为父文件`#page=ID`，因此刷新、前进/后退及单个文件转发均可用。

内页加入`about:srcdoc`基准，使`#mk1`等片内锚点继续在当前内页定位，不会递归加载分享壳。部门路由仅允许注册ID，无postMessage导航接口；未知ID回到默认页。页面缺失、data.js引用不唯一或本地媒体缺失时拒绝覆盖旧分享版，输出成功后原子替换。

部门视图是信息筛选，不是访问控制：普通页共用data.js，分享版包含多个部门数据。将来若有保密级别要求，应单独设计服务器权限与数据下发范围，不能以隐藏卡片代替权限。图文照片支持离线；Amazon远程商品图断网可能不可见，榜单文本、排名和价格不受影响。
