# RPA数据 · 模拟操作采集总索引

> 本目录是本项目所有**模拟操作（浏览器RPA / computer use）收集信息**的唯一归集地：提示词手册、逐任务执行prompt与落盘数据均在此，不再分散。
> 通用铁律：AutoGLM/浏览器代理模拟真人浏览，**禁止脚本爬虫**；验证码/风控即停不绕过；失败回报原因、不编造数值；低频访问（≤每日1次），限内部研究用途。

## 一、目录结构

```
RPA数据/
├── 00_总索引.md                ← 本文件：按数据获取方法分类归纳
├── RPA任务提示词.md            ← 提示词手册（13条目，每条含锚点校验+输出路径+upsert规则，可直接粘贴ZCode定时任务）
└── 我爱音频网评测/
    ├── 索引.md                 ← 入板登记+同步约定（迁移自标准化任务每日评测模块，2026-11-05）
    └── <YYYYMMDD>/<产品名>/    ← 评测正文+照片+_meta.json（生成数据.py 的唯一内容来源，供P91图文卡）
```

两类条目的形态差异：
- **手册类**（13条目在 `RPA任务提示词.md`）：单段提示词粘贴定时任务，产出写 `CSV数据/`，与脚本采集同 schema 同规范。
- **独立图文类**（P91评测）：采集在标准化任务侧（`研报数据整理/标准化任务/prompt目录/我爱音频网/每日评测/`，AutoGLM 浏览器代理，每日20:30），已采集文章按其 `索引.md` 契约**同步副本**落本目录（正文md+照片+_meta.json），由 `看板/生成数据.py` 扫描内联进 data.js，不落CSV。

## 三、方法分界判据（何时该用RPA）

- **走脚本**（采集脚本/collect_P*.py）：公开页面、公开API、仅需反爬伪装即可访问的源。
- **走RPA**（本目录）：登录墙（需账号会话）、强JS渲染且无公开接口、平台风控严格（如企查查）。
- 详见 `docs/数据治理/10_采集器开发规范.md` §6「RPA与脚本的边界」；已脚本化的条目不得保留RPA双轨。

## 四、运行与维护要点

1. **定时任务**：手册提示词可直接粘贴到 ZCode 定时任务（本项目工作区内创建）；已创建的任务绑定创建时的提示词副本，改手册不会自动更新存量任务。
2. **路径机制**：所有写入路径为工作区相对路径 + 开头【锚点校验】；任务必须在本项目工作区运行，防粘错工作区写丢数据。
3. **失败处理**：回报失败原因即可，禁止编造数值补位；连续失败3次人工复核来源是否改版。
4. **口径变更**：来源改版导致字段含义变化时，先回报样例数据，确认后再改CSV列。
5. **新增条目**：发现新受限源时按手册格式在 `RPA任务提示词.md` 追加（工作区相对路径+锚点校验），并同步登记本索引。
