# 图文数据 · 图文卡数据总索引

> 本目录是主看板**图文卡数据**（全文+照片+_meta.json 契约）的统一归集地。
> 两个条目均为 **PY 脚本采集**（非模拟操作）：P90 走 curl_cffi（过充电头网 JS 验证，与 P60 同通道）、P91 走 requests 直连（52audio 无反爬）。
> 通用约定：失败回报原因、不编造数值；低频访问（≤每日1次，各3篇/日上限），限内部研究用途；文章URL为去重主键。

## 一、目录结构

```

│   ├── 索引.md                 ← 通道演进/采集契约/已入板清单

    ├── 索引.md                 ← 采集契约/已入板清单

```

## 三、数据契约（生成数据.py 的唯一内容来源）

每篇文章夹一个 `_meta.json`：产品名 / 品类tag / 发布日期 / 原文链接 / chips(≤6，数值照录原文) / 摘要(两句内) / 照片(文件名清单)。
`看板/生成数据.py` 扫描 `图文数据/*/*/*/_meta.json`，按发布日期取各卡最近 6 篇，照片压缩（宽320px JPEG）base64 内联 data.js。

**chips/摘要 提炼**：机械采集只落正文与图（基础 _meta.json 带「待提炼」标记），由每日 21:15 定时任务 AI 读正文提炼后删除标记。短稿（段落<6）、外链视频稿不入库。

## 四、运行要点

1. 采集器随 `run_all.py` / `更新看板.bat` 每日自动执行，也可单独运行（参数=本次最多采集篇数）。
2. 回填：`python collect_P90_…py 6` 直接带篇数参数。
3. 手动同步（P91备用通道）：`python 我爱音频网评测/同步构建.py`——把标准化任务「每日评测」AutoGLM 新采文章复制入板，URL 去重与脚本采集互不冲突。
4. 过程帧/站方旧素材不入库（.gitignore 规则：`配图*.jpeg`）。
